## Defects found and fixed

1. **NGINX never listened on 443.** The package's default site held wildcard
   sockets on port 80. A reload binds the new 443 sockets, fails to bind the
   address-specific port 80 sockets, retries for about two seconds and then
   keeps the old configuration. Fixed: the step restarts NGINX when the
   site changes or a wildcard listener exists on 80/443, and requires an
   HTTPS request to `127.0.0.1` to succeed before reporting success. A first
   fix that only checked "is 443 bound" passed inside NGINX's retry window
   and was replaced.
2. **Code-ownership check failed on symlinks.** The venv's `python`,
   `python3`, `python3.14`, `𝜋thon` and `lib64` links report mode 777.
   `verify.sh` now ignores symbolic links.
3. **Failures through `die` were not recorded.** The ERR trap does not run
   on an explicit `exit`, so the state file stayed at `in_progress`.
   Failures are now recorded from an EXIT trap (`failed:<step>`).
4. **Version leak and wrong 404 status.** The HTTP redirect block sent
   `Server: nginx/1.28.3 (Ubuntu)`; unknown paths returned the 404 page with
   status 200. Both fixed in the NGINX template.
5. **Small things:** `started_at` was overwritten on resume; the self-signed
   certificate listed `veyra-dev1` twice (hostname equals FQDN); release
   names did not show that the source tree had uncommitted changes (now
   `-dirty`); IPv6 setup URLs lacked brackets; a reinstall after
   `uninstall.sh` was labelled an unfinished installation; the upgrade
   summary read "from 0.1.0-dev.0 to 0.1.0-dev.0".
