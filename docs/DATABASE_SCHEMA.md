# Database Schema

PostgreSQL is the authoritative store. The schema is defined by SQLAlchemy
models (`backend/veyra/core/models/`) and Alembic migrations
(`backend/veyra/migrations/versions/`). CI runs `alembic check` to make sure
the two agree. Constraint names follow a fixed naming convention.

## Core tables (migration `0001`)

| Table | Purpose | Key columns / constraints |
|---|---|---|
| `installation` | Single row: identity of this installation | `instance_id` (permanent UUID for HA and central management), `deployment_mode` (`standalone` or `ha`), `multi_tenancy_enabled`, `central_management_enabled`, `setup_completed_at`, `ha_epoch` and `ha_frozen` (migration `0029`, M16: the cluster epoch replicated to the standby, and the switchover freeze) |
| `organizations` | Tenants | `slug` unique, `timezone`, `is_active`; `engine_namespace` unique (migration `0027`: empty for the organization that predates M14, which keeps today's engine names; `[a-z0-9]` otherwise, [MULTI_TENANCY.md](MULTI_TENANCY.md) §2); `provisioning_user`, `provisioning_secret_ciphertext` (migration `0011`: the enrollment credential, purpose `organization.provisioning_secret:<id>`) |
| `sites` | Locations of an organization | `organization_id`, unique (`organization_id`, `slug`), civic address (future dispatchable location); `emergency_caller_id_number` (migration `0011`, default for the site's extensions) |
| `buildings` | Buildings at a site | `site_id`, unique (`site_id`, `name`) |
| `departments` | Departments | unique (`organization_id`, `name`) |
| `users` | Accounts | `email` unique (stored lower-case), `password_hash` (Argon2id, NULL for SSO-only), `auth_source`, `is_recovery_admin`, `home_organization_id`, lockout fields, `password_changed_at` and `must_change_password` (migration `0002`), `mfa_required_at` and `mfa_grace_until` (migration `0004`) |
| `permissions` | Permission catalog (core + modules) | `key` PK, `module_id` |
| `roles` | System and custom roles | unique (`organization_id`, `key`); `is_system` |
| `role_permissions` | Role → permission | composite PK |
| `role_assignments` | User ↔ role in a scope | `scope_type` ∈ platform/organization/site, with a check constraint for consistent scope columns |
| `sessions` | Server-side sessions | `token_hash` unique, `csrf_token_hash`, `expires_at`, `last_seen_at`, `revoked_at`, `ip_address`, `user_agent`; `mfa_verified_at` (NULL = pre-authentication session) and `mfa_failures` (migration `0004`); rows past retention are deleted by the worker |
| `mfa_methods` | Second factors (migration `0004`) | `type` (`totp`), `label`, `secret_ciphertext` (installation key), `credential` (WebAuthn, later), `last_used_step` (replay protection), `confirmed_at` |
| `mfa_recovery_codes` | Single-use recovery codes (migration `0004`) | `code_hash` (Argon2id), `used_at` |

| `audit_log` | Append-only audit trail | indexed by time and organization; **UPDATE/DELETE blocked by trigger** `audit_log_append_only` (DELETE allowed only with `SET LOCAL veyra.audit_retention='on'`) |
| `system_settings` | Key/value settings | e.g. `central.membership` (M15: console address and key, this instance's encrypted signing key, accepted sections, last policy and results, log), `central.notice`, `central.console` (console on/off and key), `setup.token` (hash plus expiry), `updates.metadata_sequence`, `telephony.sip` (SIP and media settings, M3), `telephony.numbering` (numbering plan, M4), `telephony.pending_change` (set by any engine-relevant save until the next deployment), `security.mfa` (two-factor policy, M4b), `ha.service` (service name, address, prefix, interface, replication mode), `ha.fencing` (Proxmox URL, token id, VM ids; the token secret encrypted with the installation key), `ha.sync` (recordings included?), `ha.join_tokens` (hashes, M16), `retention` (days per data class, M17) and `retention.last_run`, `backup.settings` (M17) |
| `extensions` | Extensions (engine-neutral) | unique (`organization_id`, `number`); `endpoint_name` globally unique (`<org slug>-<number>`); numbers unique per organization (migration `0027`; enforced by the API with an advisory lock per organization and number); `sip_secret_ciphertext` (AES-256-GCM token, installation key) and `sip_secret_changed_at` (migration `0003`); `emergency_caller_id_number` (migration `0010`, presented on emergency routes) |

| `installed_modules` | Module registry | `module_id` PK, `version`, `state`, `trust_level`, `signature_verified`, `manifest` (JSONB) |

| `webhook_deliveries` | The outbox (migration `0026`) | `webhook_id` `CASCADE`, `event`, `payload` (the envelope as sent), `status` (`pending`/`delivered`/`failed`), `attempts`/`max_attempts`, `next_attempt_at`, `response_code`, `duration_ms`, `error`, `response_excerpt`; kept 7 days, at most 100 per webhook |
| `central_instances` | Instances enrolled with this console (migration `0028`, M15; [CENTRAL_MANAGEMENT.md](CENTRAL_MANAGEMENT.md) §7) | `instance_id` primary key (the instance's own `installation.instance_id`); `label`, `name`, `version`, `public_key` (Ed25519), `policy_id` `SET NULL`, `enrolled_at`, `last_seen_at`, `last_address`, `last_report` (JSONB), `revoked_at` |
| `central_samples` | Counts per check-in for the console graphs (migration `0028`) | `instance_id` `CASCADE`, `at`, `registered`, `active_calls`, `extensions`, `alerts`, `status`; kept 30 days |
| `central_policies` | Policies (migration `0028`) | `name` unique, `description`, `document` (JSONB: `updates`, `firewall_allow`, `alert_recipients`, `notice`), `version` (raised on every change), `is_default` |
| `central_commands` | Commands for instances (migration `0028`) | `instance_id` `CASCADE`, `kind` (`check_updates`, `download_update`, `approve_update`, `refresh_catalogs`), `arguments`, `created_by`, `expires_at` (a day), `delivered_at`, `completed_at`, `outcome` (`ok`, `failed`, `refused`, `expired`), `message` |
| `central_enrollment_tokens` | One-time enrollment tokens (migration `0028`) | `token_hash` unique (SHA-256; the token is shown once), `label`, `policy_id` `SET NULL`, `created_by`, `expires_at`, `used_at`, `used_by` |
| `central_nonces` | Replay guard for signed messages (migration `0028`) | `nonce` primary key, `seen_at`; pruned after 10 minutes |

Since migration `0027` the `number` of `ring_groups`, `call_queues`, `paging_zones`, `pages` and `voicemail_boxes` is unique per organization (`organization_id`, `number`) instead of across the installation; slugs stay unique across the installation.

Tenant-owned tables (`sites`, `buildings`, `departments`, `extensions`,
`devices`, `device_profiles`, `paging_zones`, `inbound_routes`, `time_conditions`) carry `organization_id` with `ON DELETE RESTRICT`, so deleting an
organization never silently removes telephony data.

## Module tables

Each module owns tables prefixed `mod_<name>_` and its own version table
`alembic_version_<module id>`. Example: `mod_example_notes_note`.
