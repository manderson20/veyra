# 0014: One installation key encrypts server-readable secrets at rest

**Status:** Accepted (2026-10-12).

**Context:** SIP secrets (Milestone 4) and TOTP secrets (Milestone 4b) must
be readable by the server, so they cannot be hashed like passwords. Storing
them in clear in PostgreSQL would make every database dump a credential
leak, and database dumps travel further than the server's configuration
directory (backups, support cases, HA replicas). Options considered:
PostgreSQL `pgcrypto` with a key in the database (no separation from the
dump), a key per organization (more keys to lose, no benefit before
multi-tenancy), an external KMS (not available to a self-hosted school or
municipality), and one symmetric key kept in `/etc/veyra` next to the other
installer-generated credentials.

**Decision:** One 256-bit installation key per installation, generated by
the installer into `/etc/veyra/secrets/installation.key` (0640 root:veyra,
hexadecimal), never regenerated automatically, read by the API, the
deployer and the console command. Values are encrypted with AES-256-GCM
using a random 96-bit nonce and a *purpose* string as associated data
(`extension.sip_secret:<id>`, `config_revision.file:<revision>:<path>`,
later `user.totp_secret:<id>`), producing versioned tokens
(`v1:<base64url>`). The sensitive files of configuration revisions are
encrypted with the same key; non-sensitive files remain readable. The
`cryptography` package already in the dependencies provides the primitive.

**Consequences:** A database dump and a copy of `/etc/veyra` are both
needed to recover credentials, and both must be backed up; losing the key
means rotating every SIP secret. The key must be identical on both nodes of
an HA pair (enrollment copies it). Purpose binding stops ciphertexts from
being moved between rows. Key rotation with re-encryption is deferred to
the production hardening milestone, as is encrypting the generated engine
files themselves (Asterisk has to read them in clear). The token version
prefix leaves room for a different scheme later without ambiguity.
